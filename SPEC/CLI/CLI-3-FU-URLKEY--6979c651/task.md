## Description

Field evidence (2026-08-07) from a real external agent that migrated across tonight's
plaintext->TLS switch live. From the reporter's own cursors.json, TWO entries for ONE agent id:

{agent_id: ...mic-array-1, bus_url: http://127.0.0.1:18080,  cursor: ...|266}
{agent_id: ...mic-array-1, bus_url: https://127.0.0.1:18080, cursor: ...|266}

client/store.go (and cursorstore.go) key the persisted watch cursor by bus_url INCLUDING scheme, not
by bus id or agent id alone. The https entry started empty, so the new watch after the TLS flip
re-received all 13 messages from seq 3 -- the client had no memory that this was the same bus it had
already watched under http://.

At-least-once delivery permits this and message_id dedup absorbs it (see the positive-evidence note
filed on CLI-3, public_id 6e70abe5-ab09-4625-a62a-4a6696ae0841, for the integrity evidence from this
exact replay) -- but the scope of the effect is the point: THIS WILL HAPPEN TO EVERY AGENT
SIMULTANEOUSLY the moment TLS is required/flipped on a bus, not to one unlucky agent. Any handler that
is not genuinely idempotent (e.g. one that reacts to every inbound message rather than deduping on
message_id itself) will re-act on its ENTIRE message history at once, all at the same moment, the
first time it watches post-flip.

Not necessarily wrong -- the server-minted bus id (invariant 2, `<bus-id>.<agent-id>`) is the correct
durable key for 'is this the same bus', not the URL scheme a client happened to dial it with (the
same bus is reachable at both http:// and https:// URLs during a migration window, or after a
DNS/reverse-proxy change, or a port move -- all of which are the SAME bus and should share ONE
cursor). Rated P2: no correctness violation given dedup, but it is a real, entirely predictable
mass-replay event worth fixing (key the cursor store by bus id, not bus_url) and, regardless of
whether it is fixed, worth a migration note in AGENT_PROTOCOL.md / CONTRACTS-AGENT.md so an operator
flipping a bus to TLS knows every connected agent's next watch will re-deliver its whole history.
