## Description

RELAY-27's severance guard (internal/relay/signed.go, cause := err; if ErrorCode(err) != CodeInternal { cause = nil }) classifies a trust error ONCE and keeps the cause only if that one classification says CodeInternal. A CrossBusTrust implementation whose returned error has a STATEFUL Is() method -- answering false on the guard's classifying probe, then true when relayhttp.go's ingress later asks -- can still slip a relay sentinel (e.g. ErrRelayLoop) through and hijack the ingress outcome (e.g. converting a refusal into 200 accepted:false dropped_reason=loop), the exact class of defect the guard exists to close.

This is an ACCEPTED residual, already documented in-code at internal/relay/signed.go (the ACCEPTED RESIDUAL comment adjacent to the severance guard, committed as part of RELAY-27, commit 06e3cc5): no single classification can be immune to an Is() that lies about its own state, and reaching it requires a HOSTILE in-tree CrossBusTrust implementation -- i.e. an attacker already inside the trust boundary (CrossBusTrust is server-side, in-process code, not something a peer or client supplies). The security gate's own verdict on RELAY-27 rated it LOW and explicitly said 'not worth a second probe or a defensive copy'.

Filed per the security gate's own request: put the acceptance ON THE RECORD in the backlog, not only in a comment nobody outside the file will see.
