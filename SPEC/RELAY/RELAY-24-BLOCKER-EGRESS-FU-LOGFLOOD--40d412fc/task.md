## Description

The egress seam is what first put Forwarder.Enqueue's whole WARN set under writeMu. Four lines are drivable at volume by any ENROLLED LOCAL AGENT, synchronously, with no throttle:
- cmd/agent-bus/relayegress.go:286 -- a sender with no messaging public key, which is an optional and legitimate roster state.
- internal/relay/forward.go:862 -- THE WORST ONE, AND THE ONE TO LEAD WITH. A peer registered by INBOUND handshake gets baseURL = "" (internal/relay/registry.go:265-271), and SetPeerBaseURL is only ever called at startup (cmd/agent-bus/main.go:1156) -- so that peer has no address for the whole process lifetime. Registry.Route admits by BUS HALF alone (registry.go:495-510), so any local agent DMing <thatpeer>.<anything> pays a full ~29us ed25519 attestation mint (because routesToSomePeer returns true) plus a synchronous stderr write, per message, under writeMu. One agent can stall every other agent's send.
- internal/relay/forward.go:925 and :971 -- capacity / queue-full, self-sustaining once a peer is down.
internal/logging has no rate limit or dedup. The remedy pattern already exists in this repo at internal/store/store.go:509 (log-once + counter, whose comment is explicitly "to deny a peer a log-flood"); it is simply not applied here. Note this is LOCAL-agent-drivable, not peer-drivable -- which is why the security gate rated it non-blocking.
