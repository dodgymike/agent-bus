## Description

Raised by the security gate on RELAY-24-BLOCKER-PEERCERTFLAG (P2, does not block). A roster AGENT's client-certificate binding (internal/auth/certbind.go:193-205) and a relay INBOUND PEER binding (relay.BusTrustRecord.PeerClientTLSCertFingerprint) live in separate namespaces with no uniqueness check between them. An operator who pastes an AGENT's certificate fingerprint into `agent-bus peer add -peer-client-fingerprint` would let that agent resolve to a BUS principal on /v1/peer/*. Requires operator error to reach, and it fails closed for everything else. THE FIX BELONGS IN THE STORE, NOT THE CLI: a CLI-side check would be a TOCTOU window on exactly the property it defends, mirroring why PutTrust's existing ErrPeerClientCertAlreadyBound check runs inside build() under s.mu+writeMu. Needs a decision on which layer owns cross-namespace fingerprint uniqueness first. proof_cmd must show a bind of an agent's fingerprint as a peer binding being REFUSED.
