## Description

RELAY-34 added PeerStoreOptions.Dir, the data directory holding <data-dir>/peer-withdrawal-floor. Anything constructing a relay.PeerStore MUST set it. cmd/agent-bus/peer.go (relay.NewPeerStore at ~:954 and ~:976) does NOT, because it is a different agent's file and RELAY-34 was boundary-scoped out of it.

CONSEQUENCE, which is deliberate and fail-CLOSED but currently BROKEN-BY-DEFAULT: Remove and RemoveTrust return relay.ErrPeerNoWithdrawalFloor on a store built without Dir, so 'agent-bus peer remove' / 'remove-trust' -- the place an operator actually types a revocation -- will refuse outright until Dir is passed. Puts, reads and Apply are unaffected. This is the correct failure direction (a store that cannot record a withdrawal outside the log must not report a revocation it cannot make stick) but it means the CLI revocation path does not work until this lands.

FIX: pass Dir (the data directory, the same one the wal.Log lives in) at both construction sites. Note the store is then NOT read-only on disk even without a Durable: Apply repairs the withdrawal floor from the log, so the single-writer/dirlock rule binds the READ path too -- peer.go already holds the dirlock on both paths, so this is satisfied, but do not construct a PeerStore with a Dir outside the lock.

PROOF: an 'agent-bus peer remove-trust' against a real data directory must write peer-withdrawal-floor and must not return ErrPeerNoWithdrawalFloor. BLOCKS the observable-behaviour half of RELAY-12 and RELAY-24.
