## Description

There are now FOUR production copies of the temp-file + fsync + rename + directory-fsync sequence: internal/ids/atomicfile.go's atomicWriteFile (shared by ids/busid.go and ids/suffixstore.go), internal/wal/indexfloor.go's atomicReplaceFile, internal/hub/seqfloorfile.go's atomicReplaceSeqFloor, and internal/relay/peerstore.go's atomicReplacePeerWithdrawalFloor (added by RELAY-34).

Every step is load-bearing and each is a SILENT, undetectable-by-test omission if dropped from one copy: fsync the FILE before the rename, fsync the DIRECTORY after it, keep the temp file in dir so the rename is an intra-filesystem swap, chmod 0600 before any content is written. A fix applied to one and not the others leaves a durability hole in whichever was missed, and no test on a machine that does not crash can see it.

Task 1aed37a9-3a8e-4940-8b36-ee2dbe28afb5 already removed the duplication INSIDE package ids and left an AST guard in ids/atomicfile_test.go enforcing one copy there. This is the cross-package version: export a shared helper (it cannot live in internal/ids as-is because internal/relay must not import internal/wal, and the helper must not drag the WAL in). Behaviour-neutral refactor, so it needs its own task rather than riding along with a feature.

RELAY-34's copy documents this honestly at internal/relay/peerstore.go (see the atomicReplacePeerWithdrawalFloor doc).
