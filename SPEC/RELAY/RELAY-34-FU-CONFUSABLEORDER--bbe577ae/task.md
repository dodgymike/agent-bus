## Description

reconcileWithdrawalFloor skips records the table refused on IDENTITY grounds -- a self-peer, and a bus id differing only by ASCII case from one the table already holds. The second guard is ORDER-DEPENDENT: it can only fire once the table HOLDS the legitimate record to compare against, so a confusable 'removed' record replaying FIRST against an empty table is still floored, under the FOLDED key.

The gap is DELIBERATE and the comment at internal/relay/peerstore.go states it in full, because closing it would break the mechanism: the only broader rule available is 'do not floor a withdrawal for a bus the table does not already hold', and that is precisely the case the floor exists for (a tombstone whose ACTIVE record was discarded arrives with nothing in the table).

RESIDUAL HARM, verified by the reviewer gate against HEAD behaviour: it is NOT a new un-pinning. The confusable occupies the slot and the legitimate bus is refused either way, matching pre-RELAY-34 behaviour; what remains is a permanent floor row nothing can explain or remove, consuming one of maxPeerWithdrawalFloorEntries (4096). Reachable only by FORGING a WAL frame -- nothing outside internal/relay emits these record kinds, and the keyed HMAC means the non-adversarial triggers (bit-rot, torn writes, snapshot rollback) can only DROP records, never invent one.

Filed so the residual is tracked rather than only commented. Any fix needs a way to distinguish 'first sighting of a legitimate bus' from 'first sighting of a confusable', which probably means a durable canonical-spelling registry rather than a change to reconcile.
