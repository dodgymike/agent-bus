## Description

Filed 2026-08-14 from the RELAY-24-BLOCKER-HUBINGEST security gate. LOW.

hub.IngestRelayed performs NO signature or attestation verification, and that is CORRECT -- verifying the origin signature against the origin bus's pinned key is internal/relay's job. What is missing is any enforcement that the CALLER did it. Because IngestRelayed is EXPORTED, a future caller can reach the two-phase write path with an unverified relayed message and nothing complains.

PRECEDENT: internal/relay already defends the equivalent seam with an AST guard (internal/relay/guards_test.go, CrossBusTrust). Consider the same shape for this entry point -- a test that walks the AST of every caller of hub.IngestRelayed and asserts the signature verification is present on the path.

Note the guard's value is exactly the value of the client/pin.go AST guard: the positive tests pass either way, so only a structural check catches the omission.
