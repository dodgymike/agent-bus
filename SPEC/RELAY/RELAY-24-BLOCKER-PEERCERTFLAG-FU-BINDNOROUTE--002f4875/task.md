## Description

Raised by the security gate on RELAY-24-BLOCKER-PEERCERTFLAG (P2, does not block). `peer add -bus-id X -signing-key K -peer-client-fingerprint FP` with NO -url writes a trust record that makes bindablePeerCount (cmd/agent-bus/relaywiring.go) non-zero, so the /v1/peer/* ingress mounts -- even though nothing can ever present that certificate if the topology has no path to that bus. It fails CLOSED (403), but it is exactly the "registered and refusing to everyone" state the mount gate exists to prevent, per relaywiring.go's own comment. Decide whether a trust-only binding should count toward the gate, or whether the gate should also require a route, or whether this is legitimate (an inbound-only peer that dials US and is never dialled is a REAL topology -- the laptop-behind-NAT case -- in which case the gate is right and only the doc needs the caveat). Do not "fix" it before deciding which of those three it is.
