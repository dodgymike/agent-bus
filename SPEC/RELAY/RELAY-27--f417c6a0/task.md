## Description

internal/relay/signed.go:306 wraps its inner error with %v, not %w: `fmt.Errorf("%w: sender %q: %v", ErrNoSignerKey, m.Sender, err)`. Once RELAY-17 routes attest.Verify through CrossBusTrust.AttestedSignerKey and this seam, errors.Is(err, attest.ErrExpired) is FALSE at every caller -- an expired attestation is misreported as belonging to the ErrNoSignerKey/no-signer-key family instead of its own distinguishable expiry sentinel. FEDERATION_TRUST_DEEPDIVE.md 4.2/4.4 explicitly forbid that misattribution. Fix: change the inner %v to %w (Go supports at most one %w historically, but 1.20+ allows multiple %w verbs -- verify go.mod version and use multi-%w if available, otherwise restructure with errors.Join or a wrapped-error type so both ErrNoSignerKey and the specific attest sentinel (e.g. attest.ErrExpired) are matchable via errors.Is). Add a regression test asserting errors.Is(err, attest.ErrExpired) is true when AttestedSignerKey returns an expired attestation. Flagged by the RELAY-14 security gate (P2-4) and repeated here as a P1 because RELAY-17 depends on this seam directly. Also posted as a note on RELAY-17 so its implementer has this in hand before starting.
