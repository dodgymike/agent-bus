## Description

ACK-8 proved ack state is correctly reconstructed by full WAL replay across restart, torn tails and crashes, but replay time is still UNBOUNDED: it is O(every ack record ever written, less retention sweeps). ACK-8's description asked to "reuse WAL checkpoint generations rather than adding an independent snapshot"; that could not be done in ACK-8 and the reason is structural, not effort:

- `LogOptions.Checkpoints` has ZERO production assignments. `cmd/agent-bus/main.go` passes `Applier`, so `Log.Checkpoint` always errors (`internal/wal/checkpoint.go:225-227`).
- It is fail-closed in the WORST direction. `internal/wal/log.go:829-831` refuses the WRITE of any unowned kind and `internal/wal/checkpoint.go:92` makes an unowned kind a hard error on Apply, poisoning the log with `ErrDiverged` on a live write and failing Open on recovery. **Flipping `Applier` to `Checkpoints` today would refuse every message publish and every enrolment.**
- Only `relay.Outbox` implements the `Name/Kinds/Snapshot/Restore` participant interface. Seven other production kinds do not (message, seqfloor, agent, agent+invite, invite, peer/bustrust, ack).

So this is a WAL-wide task, not an ack task: every production kind needs a checkpoint participant before `Checkpoints` can be assigned at all. Scope it as such. `internal/ack/doc.go` already states this debt is ACK-8's; that note should be updated to point here when this lands.
