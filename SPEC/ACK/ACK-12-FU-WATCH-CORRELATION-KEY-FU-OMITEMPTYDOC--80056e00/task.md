## Description

`internal/httpapi/messages.go:279-283` and the matching paragraph in `AGENT_PROTOCOL.md` justify `correlation_key` never being `omitempty` by saying omitempty would drop the field "on a same-bus message". That is wrong: `omitempty` drops only `""`, and `store.Message.OriginID()` returns `m.ID` for a same-bus message, so the field would be present anyway. The comment's own next sentence concedes it. The REAL argument -- the one `TestWatchRecordAlwaysEncodesCorrelationKey` actually pins -- is the CLI's `watchRecord` against an OLD bus that does not send the field, where the value IS `""`: with `omitempty` that becomes a `null`, and in jq `null` is falsy while `""` is truthy, so the idiom `.correlation_key // .message_id` would SILENTLY resolve to the wrong id instead of failing loudly. Behaviour is already correct and pinned by tests; this is a comment/prose correction only. Raised by the reviewer on `f423959c` as a non-blocking follow-up.
