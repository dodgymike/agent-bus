# The defect

The closed ACK vocabulary -- the 12 NACK classes, the attestation values and the lifecycle states
ruled by ACK-1 -- is declared TWICE, in two packages, with DIFFERENT UNDERLYING TYPES:

  internal/ack/state.go:30   type State       uint8
  internal/ack/state.go:146  type Class       string
  internal/ack/state.go:233  type Attestation string

  internal/relay/ack.go:183  type AckClass       uint8
  internal/relay/ack.go:437  type AckAttestation uint8

Class is a STRING in one and a uint8 in the other. This is not cosmetic duplication: it is two
independent representations of one closed set that must agree forever, across a package boundary,
with no compiler relationship between them.

# Why this is the repo own worst pattern

internal/store/message.go:437 refuses to add a Pos field to store.Record on the stated grounds that
it would create a second copy free to disagree with the first. That is exactly what has happened
here. The Seq vs Pos vs OriginMessageID conflation has already caused THREE defects in this codebase
for the same reason.

A closed enum that exists twice is not closed. The failure mode is silent: one side gains a
thirteenth class, the other rejects it as unrecognised, and the refusal looks like a protocol
violation rather than version skew.

# How it happened -- not anyone mistake

ACK-2 and ACK-4 were deliberately run IN PARALLEL off the ACK-1 contract with disjoint file
ownership. ACK-4 stayed self-contained on purpose so it could verify against HEAD alone, and
recorded the duplication in its own report rather than reaching into another agent uncommitted
package. That was the right call at the time. This task is the cleanup that decision implies.

# Scope

Pick ONE home and make the other consume it. Decide which, and record why:
  - internal/ack is the natural owner by name and already owns the lifecycle State.
  - internal/relay/ack.go owns the authorization logic carrying 18 mutation-proven guards; those
    guards must survive the move UNCHANGED and be re-proven RED afterwards.

Constraint: the client package cannot import internal/ (invariant 7). If any part of this vocabulary
must ever be visible to an embedding agent, it cannot live under internal/ at all -- settle that
BEFORE moving code, not after.

# Acceptance
  - the 12 classes, the attestation values and the states are declared exactly ONCE
  - a test proves the former call sites agree, or better, the second declaration is gone
  - every ACK-4 guard is re-proven RED by mutation after the move; a guard that survives a refactor
    unproven is a guard nobody has checked
  - the ACK-1 contract sections are updated to name the single home

# Do NOT
  - do not change any class, value or state as part of this move. A de-dup that also edits the
    vocabulary makes the diff unreviewable and the mutation proofs unrepeatable.
