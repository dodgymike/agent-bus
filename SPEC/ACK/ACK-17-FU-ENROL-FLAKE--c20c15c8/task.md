## Description

TestCLIEnrolEndToEnd (cmd/agent-busctl/enrol_test.go:88) requires primeCmd.Wait() to return nil
after the test sends SIGTERM to the priming server. When the signal lands before the server
installs its own signal handler, the process dies on the default disposition and Wait() returns
"signal: terminated" instead of nil, failing the test.

Reproduced at PRISTINE HEAD (main, no other task's files present): 3 of 5 runs failed under
go test -race -run TestCLIEnrolEndToEnd -count=5 ./cmd/agent-busctl.

This matters beyond its own flakiness: it fails INSIDE other tasks' stored proof_cmd invocations that
happen to include ./cmd/agent-busctl in their package list (e.g. the original ACK-17 proof_cmd
"go test -race ./internal/httpapi ./cmd/agent-busctl"), making those stored proofs unreliable --
a proof that intermittently fails for a reason unrelated to the change it is meant to prove is not
a proof. Both the reviewer on ACK-17 and feature-runner (independently) hit this failure.

Fix direction (not yet investigated in depth): either have the priming server install its SIGTERM
handler before signalling readiness to the test harness (a synchronization/ready-signal fix), or
have the test retry/tolerate an early-SIGTERM race, or switch the priming server's shutdown signal
to one the test can sequence deterministically after handler installation.
