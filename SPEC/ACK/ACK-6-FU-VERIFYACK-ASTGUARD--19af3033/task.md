## Description

ACK-CONTRACT.md 6.3 requires that NO bus verifies a recipient attestation and none may claim to -- relay.ValidateAckAttestation checks SHAPE ONLY and the status API has exactly two labels, peer_bus and recipient_signature_unverified, with deliberately no value meaning "verified". internal/signing now exports VerifyAck. It has zero non-test callers and the security gate judged that exporting it is CORRECT (unexporting would push a future sender to hand-roll verification, which is the invariant-9 silent failure), but flagged that the temptation is more real than the doc allows: internal/relay/signed.go:606-624 ALREADY resolves an attested messaging key and calls ed25519.Verify on a bus ingest path. Fix: add an AST guard in the style of the nine existing in-repo precedents (see client/guard_test.go) asserting that signing.VerifyAck has no caller outside _test.go files and outside any future sender-side verification site added deliberately to an allowlist. Raised by the security gate. Prospective files: internal/signing/ or internal/relay/ guard test.
