## Description

The human (non-`--json`) `watch` render prints `  ack key: <key>` at `cmd/agent-busctl/watch.go:455` with a two-space indent. `writeHumanMessage` renders a multi-line body's continuation lines with the SAME two-space indent (`cmd/agent-busctl/watch.go:485-487`), so a sender can put `ack key: <id-of-its-choosing>` on its own line in a multi-line body and produce byte-identical output. On a SAME-BUS message, where the genuine line is deliberately suppressed because the key equals `message_id`, the forged line is the only one present. Impact is bounded -- `POST /v1/ack` answers the uniform `unknown` for any key the caller was not a recipient of, so the worst realistic outcome is a false delivery/refusal receipt on another message the victim did legitimately receive. Pre-existing IN KIND (any body could always forge an indented line); newly meaningful because there is now a semantically actionable line to forge. Minimal fix: render the ack key at COLUMN 0 -- a single-line body prints on the header line and every multi-line body line is indented, so column 0 is unforgeable. Raised by the security gate on `f423959c` as LOW and non-blocking; the reviewer independently reached the same conclusion. `--json` is unaffected and is the agent-facing surface invariant 7 governs. Needs a test that asserts a crafted multi-line body cannot produce a line indistinguishable from the genuine one.
