## Description

FILED 2026-08-21 by main, from the ACK-16 security gate (non-blocking).

The parked-wait cap is per principal and there is NO GLOBAL ceiling. Worst case is 32 x enrolled
principals -- roughly 131k goroutines at the 4096 roster cap.

NOT reachable by one agent, which is why it is P3 rather than higher: the per-principal bucket holds
(ACK-16 proved it), and enrolment is invite-gated since 3cedcb7, so an attacker cannot mint principals
freely. It needs many legitimately-enrolled agents all parking at once.

Two things to weigh rather than assume:
  - whether a global ceiling is wanted at all, or whether the per-principal bound plus the invite gate
    is the intended design. Adding a global cap introduces cross-agent interference, which is exactly
    the property ACK-16 just spent effort proving does NOT exist -- do not trade it away casually.
  - the 200ms tick could back off for waits that have found nothing for many intervals; that is a cost
    reduction, not a bound.

Also noted by security: newAckStatusServer enrols without an invite gate, matching every other
internal/httpapi fixture -- so those tests would not notice a regression of that gate. Separate
concern, worth its own task if anyone cares to file it.
