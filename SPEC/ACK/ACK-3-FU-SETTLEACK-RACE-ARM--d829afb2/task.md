## Description

Raised by the reviewer gate on ACK-3 (2026-08-16) and filed rather than forced, on the reviewer's explicit instruction.

cmd/agent-bus/relaywiring.go settleAck has `case errors.Is(err, ack.ErrTerminal)`, which re-spells the durable layer's absorbing-terminal refusal as relay.ErrAckOutcomeConflict so the route's single status mapping covers both the raced and the unraced path. Measured coverage of that arm is count=0, and replacing it with a plain error leaves the suite green.

It is reachable ONLY by losing a race: settleAck's advisory Lookup must see a NON-terminal row and ack.Store.Settle must then find a terminal one, which needs a concurrent transition landing between the two. The ordinary conflict is caught earlier and correctly by relay.DecideAck, which is the point of comparing before the durable call.

Covering it requires a seam in federation.acks, which is a concrete *ack.Store. The reviewer ruled FILE IT, DO NOT FORCE IT: an interface introduced only so a test can interpose is a production indirection bought with test convenience, and it would sit on the path that decides whether an ABSORBING TERMINAL outcome is recorded.

Two priorTerminal defensive arms are uncovered for the same reason (a durable row whose state or class is outside the wire vocabulary, which no writer in this build can produce). Both fail closed.

Options for whoever takes this: a durable-log wrapper that injects a concurrent Settle between the Lookup and the Settle; or move the whole read-decide-settle sequence into internal/ack behind one lock, which would delete the arm rather than test it. The second is probably right and is a bigger change than ACK-3 could carry.
