## Description

Named by the ACK-5 reviewer gate, 2026-08-21, as "no task filed for the conflicting-terminal code fix".

On the ACK-5 transit path EVERY failure is answered 503 + Retry-After on the agent surface, and 503 CodeUnavailable on the peer surface. That is right for a transient failure -- nothing was written anywhere, so an identical retry is safe (ACK-CONTRACT.md 9.3: a 4xx is FINAL and would make the outcome be ABANDONED).

But the SAME 503 is returned when the upstream answered 409, and a 409 is PERMANENT: no obligation binds that recipient, the row was swept, or -- the important one -- a CONFLICTING TERMINAL already stands at the origin. In those cases every retry fails identically, for ever. The two are byte-identical to the client ON PURPOSE: distinguishing them would tell a bound peer whether the ORIGIN holds a row for a recipient it named, which is the uniform-answer property relay.ErrAckNotBound protects.

So today the honest client advice is "retry a handful of times, then give up", which is what ACK-5 wrote into AGENT_PROTOCOL.md and the agent-busctl ack help -- a documentation patch over a protocol gap, not a fix.

Note the asymmetry ACK-5 deliberately left: an INTERMEDIATE bus ABSORBS a 409 from the hop above it and answers its downstream 200, so on a chain of 2+ backward hops the recipient is told `accepted` for an outcome the origin refused. On a chain of exactly one hop the same 409 becomes a 503 the recipient can never clear. Same upstream verdict, two opposite client-visible answers, decided by topology the client cannot see.

Options, none free: (a) a distinct non-oracular signal meaning "final, stop retrying" that does not reveal WHICH of the three 409 causes applied; (b) accept the conflicting-terminal case as reportable (it is the one 409 cause that is arguably not a secret from a peer already bound to the key) and keep the other two uniform; (c) leave it and keep the bounded-retry advice, but make the two topologies agree. Blocked on nobody; wants a protocol decision recorded in DECISIONS.md before code.
