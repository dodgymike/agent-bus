## Description

Found by ACK-6's security gate (LOW/MEDIUM). internal/ack/store.go wraps a durable.Write failure in Settle WITHOUT ack.ErrNotDurable, so hub.AcknowledgeDelivery's errors.Is(err, ack.ErrNotDurable) arm -- which exists and maps to hub.ErrNotDurable and a 503 -- is DEAD CODE, and a real disk failure answers 500 instead of 503. Invariant 4 itself HOLDS: a non-nil error is returned, the memory copy is not moved, and nothing is acknowledged. Only the status CLASS is wrong, which matters because 500 tells a client the server broke while 503 tells it to retry -- and here a retry is exactly right. FIX: wrap with %w on ack.ErrNotDurable (or a new ErrWriteFailed that hub maps to the same arm) in Settle, and check Accept and MarkInFlight for the same shape. NOT DONE IN ACK-6 because internal/ack/store.go was staged by a concurrently-running agent (ACK-9). PROOF: a stub DurableLog returning an error, asserting errors.Is(err, ack.ErrNotDurable) and a 503 at the route.
