## Description

internal/hub/relayingest.go's relayedBusPath validates each hop and refuses a path already containing this bus, but does NOT require the last received hop to be the peer whose client certificate authenticated the request, and the relay signature does not cover BusPath. Since ACK-5 the stored path chooses which peer this bus POSTs a terminal outcome to. Contained -- the target must already be in OUR registry with a base URL, the frame names no address, and sec6.2 refuses an unowed ACK 1:1 -- but a mutually-fabricating pair of peers yields a nested ping-pong bounded only by the 8-slot per-peer meter, i.e. 1:8 rather than 1:1. The fix belongs at INGEST, not on the ACK path. Raised by the ACK-5 security gate, 2026-08-21.
