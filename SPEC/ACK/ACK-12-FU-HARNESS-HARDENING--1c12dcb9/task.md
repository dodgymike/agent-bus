SECURITY (LOW, all in tests/e2e/threebus_ack_test.go):
1. ~:349 (and via decode at ~:76/:347) — t.Fatalf(..., raw) dumps the raw invite mint document, which carries invite_secret (cmd/agent-bus/invite.go:343), into test output on a failure path. Contradicts the files own ~:368 comment. Fix: print the bus name and parsed fields, not raw.
2. ~:1176-1186 — the §13.3 oracle compares stdout only; a differing STDERR hint would leak exactly the distinction the test exists to deny. Fix: capture and compare res.stderr alongside stdout.
3. ~:251 — ctlRun passes nil extraEnv, so ambient AGENT_BUS_URL/AGENT_BUS_FINGERPRINT reach agent-busctl (env beats stored identity, client/config.go:226-229) while serve() sanitises for the server. Every redirect path fails closed on the pin, so this is hermeticity not exploitability. Fix: mirror serve() and pass empty AGENT_BUS_* overrides.
4. ~:323-327 + ~:57 — the stop-all t.Cleanup calls run(), which t.Fatalfs on launch failure; a failure stopping bus A would Goexit and LEAK buses B and C. Fix: use exec.Command(...).Run() directly in cleanup and ignore the error.
5. ~:918 — subtest name recipient_nack_is_authenticated_and_classed claims authentication, but no non-recipient ever attempts an ack (f.ack hardcodes the recipient). The control genuinely exists — internal/hub/ack.go keys rows by (correlation key, recipient) with Recipient = the authenticated principal, and internal/httpapi/ack.go:202 refuses a mismatched claimed recipient with 403 and correctly does NOT disconnect (invariant 10). Over-claiming NAME, not a hole. Fix: rename to ..._is_classed_and_attributed, or add the negative probe.
