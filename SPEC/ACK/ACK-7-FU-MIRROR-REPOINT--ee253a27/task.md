## Description

Re-point ACK-7's mirror guard so it follows the SETTLE PATH instead of one function.

# Why

ACK-7 landed as 04dde85. Its a7AssertMirrorMatchesProduction AST-scans
(*federation).settleAck and asserts a set of identifiers is present. ACK-5 keeps settleAck but
EXTRACTS the not-bound arm into (*federation).disposeUnrecordedAck. relay.ErrAckNotBound still
exists and still returns the same uniform refusal -- it simply moved out of the scanned function --
so the guard failed and BLOCKED ACK-5, plus the three commits queued behind it.

The guard was constraining the SHAPE of production rather than its BEHAVIOUR. A refactor that
preserves behaviour must not break a test whose subject is behaviour. Fixed here rather than asking
ACK-5 to keep the return inside settleAck, which would have distorted production to satisfy a test.

# What changed (test-only, zero production code)

internal/relay/ackretry_ack7_test.go:
  - a7SettlePath replaces the single-function scan: walks settleAck plus every method it calls on
    its OWN receiver declared in the same file, transitively. f.acks.Settle is NOT followed (its X
    is a SelectorExpr, not an Ident) -- intended, that leaves the file.
  - the negative assertion (nothing branches on ack.ErrConcurrentTransition) now covers the whole
    path, so an arm extracted into a delegate is still an arm.
  - NEW: the path must contain a switch with a DEFAULT arm. The negative only means something while
    there is a default for ErrConcurrentTransition to fall through TO; delete the default and the
    negative passes over code that no longer answers a concurrent transition.
  - non-vacuity: the walk must visit >=2 functions, since settleAck has always called
    f.priorTerminal. A broken delegate-follower would otherwise silently narrow the scan.
  - documented limitation: the positive checks are PRESENCE checks, so they catch an identifier
    disappearing ENTIRELY, not one call site out of several.

# Gates

reviewer PASS. Confirmed recursion terminates, receiver matching is sound, hasDefault detection is
correct, and visited>=2 can actually fail. It mutated each ErrAckNotBound arm separately and found
both have behavioural owners that go RED (cmd/agent-bus TestSettleAckDisposition,
TestSettleAckCorrelatesToTheDurableRecord), and RULED that the presence check must NOT be
strengthened -- call-site counting would reintroduce the shape constraint. Two LOW follow-ups filed
as ACK-7-FU-SETTLEPATH-GUARD.
