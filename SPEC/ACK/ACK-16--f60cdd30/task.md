# The guard that cannot fire

internal/httpapi/ackstatus.go:292 acquires the parked-request slot per principal:

    s.ackWaiters.acquire(sender)

CHANGING IT TO A GLOBAL BUCKET LEAVES THE ENTIRE internal/httpapi PACKAGE GREEN -- re-confirmed by
the reviewer WITH the newly-staged ackwaiter_internal_test.go present.

# Why that matters

With a global bucket, ONE agent parking maxParkedAckStatusPerAgent (32) requests on
GET /v1/ack/<key>?wait= locks EVERY OTHER AGENT out of the wait path. That is a cross-agent denial
of service on an authenticated route.

And it is claimed impossible in two places:
  - internal/httpapi/ackstatus.go:65-79 (the code's own doc)
  - CONTRACTS-HTTP.md:456 (a published contract)

So today the code asserts a property, the contract publishes it, and NOTHING TESTS IT. If the
per-principal keying is ever refactored away, all three stay silent.

# Also green under mutation, same review, lower stakes
  - the CLI's entire human row rendering, cmd/agent-busctl/ackstatus.go:261-281
  - the settled_at zero-check, ackstatus.go:478

# Scope

Add the test that fails when the bucket stops being per-principal. The natural shape: two distinct
authenticated senders, the first parks up to the cap, the second must STILL be admitted. Assert on
behaviour (the second sender's request is served) rather than on internals, so a refactor cannot
satisfy it accidentally.

# Standard of evidence
