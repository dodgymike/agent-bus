## Description

Decide, in `DECISIONS.md`, what the terminal interface renders with. Independent of TUI-1's replace/complement
question, so it can be decided in parallel -- but it must land before TUI-3 imports anything.

## The fact that makes this a real decision

`go.mod` today is TWO LINES of content: `module github.com/dodgymike/agent-bus` and `go 1.19`. **The project
has ZERO third-party dependencies.** A realistic TUI wants `bubbletea`, `tcell` or `termbox`. Adopting one
makes it the FIRST external dependency in the entire codebase, and it arrives with a transitive tree.

Invariant 8: "Simple beats clever. Go stdlib first. A third-party dependency needs a `DECISIONS.md`
justification." That is exactly this task. The danger is NOT that a library is wrong -- it may well be right.
The danger is that a dependency arrives as an INCIDENTAL IMPORT inside a feature task and nobody ever decides
it. Do not let TUI-3 be where this happens.

## Options to weigh honestly

- **Stdlib only.** ANSI escapes and raw-mode handling by hand. Cheapest dependency story; note that raw-mode
  terminal handling on POSIX needs `golang.org/x/term` or syscall work, so "stdlib only" may not be as free as
  it sounds -- check before claiming it.
- **A TUI framework** (`bubbletea` + `lipgloss`, or `tcell`). Best ergonomics, largest tree. Count the
  transitive modules and say the number in the decision.
- **A minimal terminal library only** (`golang.org/x/term`), with layout hand-rolled. Middle path; note
  `golang.org/x/*` is Go-team-maintained but is still not stdlib and still needs this justification.

## Requirements for the decision text

- Name the exact module path(s) and version(s), and the TRANSITIVE module count.
- Say what happens to the container build (`DEPLOY-4` pins the toolchain; a dependency changes the builder's
  network/vendoring story) and whether vendoring is used.
- Invariant 9 is NOT in play -- a TUI library does no crypto -- but say so explicitly, because "we added a
  dependency" is exactly when someone reaches for a convenience crypto helper. Any library that pulls a crypto
  package into the tree needs a second look.
- If the answer is "stdlib only", record it as a decision too. That is a legitimate and cheap outcome.
