## Description

Found during IDEM-18's documentation pass and verified independently by both the reviewer and the security gate: `idem.FromRequest` (`internal/idem/key.go`) has **zero production callers** repo-wide -- the only reference is `internal/idem/idem_test.go`.
It was written as the single place a key is read off the wire, and its own comment pointed at an 'HTTP wiring task (httpapi, out of this task's scope)' that would pass `r.Header`. **That wiring never happened**: `internal/httpapi` chose the `idempotency_key` JSON **body field** instead, and `internal/relay` reads the header directly via `r.Header.Get(idem.HeaderName)` rather than through this helper.
WHY IT MATTERS (security gate P2): the agent plane now validates keys by a SECOND path -- `internal/httpapi/auth.go`'s check plus `hub.validateIdempotencyKey` -- so one rule has two implementations that can drift. That is the actual defect; the dead function is the symptom.
IDEM-18 deliberately did NOT delete it (that is a code change beyond a documentation task) and instead documented its status honestly in `internal/idem/key.go`.
DECIDE AND DO ONE: (a) delete `FromRequest` and its test, or (b) keep it and make it the single validator both planes call. Do not leave it as a third, unused spelling of the rule.
