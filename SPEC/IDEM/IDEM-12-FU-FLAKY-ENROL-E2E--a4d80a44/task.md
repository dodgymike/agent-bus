Found while establishing a baseline for IDEM-12, at HEAD 9938eb2 with a tree byte-identical to HEAD, so it is NOT caused by that task. go test -race ./... fails with:
--- FAIL: TestCLIEnrolEndToEnd (1.00s)  enrol_test.go:88: the priming server exited badly: signal: terminated

It PASSES in isolation (go test -race -run TestCLIEnrolEndToEnd ./cmd/agent-busctl/...) and PASSES as a whole package (go test -race -count=1 ./cmd/agent-busctl/...), both verified in a clean git archive HEAD overlay. It fails only when the entire repo suite runs concurrently, i.e. a timeout under CPU/resource contention while priming a real server subprocess. The 1.00s duration against a signal: terminated suggests a fixed 1s budget that is simply too tight under load.

This matters because it makes go test -race ./... -- the broadest gate anyone runs -- red for a reason unrelated to the change under test, which trains agents to hand-wave "pre-existing failure". Either raise/derive the priming timeout, or make the test resilient to a slow start.
