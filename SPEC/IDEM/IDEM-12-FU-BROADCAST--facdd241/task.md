## Description

IDEM-12 delivered the SEND half of idempotent send/broadcast and deliberately delivered NO broadcast test. This is the tracking task for the broadcast half.

WHY IT WAS NOT DELIVERED, and why this is a gate rather than an omission: /v1/broadcast answers 501 by design (internal/httpapi/messages.go:452) because SIGN-6 admits no unsigned message type and a broadcast has no canonical audience under signing format v1. Below the route, hub.Broadcast ALSO fails closed for every broadcast: signing.Canonicalize rejects an empty recipient set, so auditContentHash (internal/hub/audit.go:169-193) errors and the send never reaches the durable write. Consequently every existing broadcast idempotency test in the repo currently SKIPS via skipIfBroadcastHasNoSigningDigest (internal/hub/hub_test.go:113), including TestBroadcastSend/IdempotentRetryReturnsOriginal, TestAppliedKeyStoreSurvivesRestart and TestIdemCrashInjectionRestartBroadcastRetryIsAnsweredOnce.

Adding a broadcast test now would ALL-SKIP, and scripts/proof-check.sh judges an all-skip leaf set VACUOUS -- it would have poisoned IDEM-12's own proof. There is also a standing operator ruling (2026-08-08, recorded at internal/hub/hub_test.go:135) against rewriting these tests to assert the refusal, because a green suite asserting "a broadcast is refused" reads as the SETTLED design.

GATED ON: SIGN-3 (f2daa6bc-53ee-4788-935c-ab73693c5e75, status todo) -- "Broadcast signature covers the recipient set". The skips are self-healing: the day SIGN-3 lands and hub.Broadcast starts succeeding, every one of those tests comes back on its own.

WHEN SIGN-3 LANDS, deliver here: a broadcast counterpart to TestIdempotentSend asserting a same-key/same-payload retry returns the ORIGINAL id+sequence, adds NO second append-only audit record, and -- IDEM-12 folded-in item (c) -- fans out to NOBODY a second time, including recipients whose delivery failed on the first attempt.
