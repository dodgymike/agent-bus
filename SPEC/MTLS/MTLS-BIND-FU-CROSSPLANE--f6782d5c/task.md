## Description

Found by the reviewer gate on MTLS-BIND and confirmed by reading the code. There are now TWO independent fingerprint->principal tables and neither consults the other:
  - PEER plane: internal/relay/peerstore.go, peerClientCertBindingsLocked (~line 3153) resolves a fingerprint to a BUS id. Uniqueness and fail-closed ambiguity are enforced WITHIN that table.
  - AGENT plane: auth roster CertBindings, internal/auth/certbind.go certFingerprintOwner resolves a fingerprint to an AGENT id. Same discipline, WITHIN that table.
So a single certificate can be simultaneously a trusted peer-bus principal and a bound agent id. Each plane is individually correct; the gap is emergent, and it only became REACHABLE when MTLS-BIND gave the agent plane bindings at all. Invariant 11's concern is exactly one principal being accepted as another.
Decide and implement: either a cross-plane uniqueness check at both write paths, or an explicit recorded decision in DECISIONS.md that the planes are deliberately disjoint and why that is safe. Do not close this by assuming it cannot happen.
