## Description

CONTRACTS-HTTP.md:831-842 carries a block headed "NOT ENFORCED: invariant 11's cross-check is DESIGNED, not LIVE", asserting that auth.Service.AgentIDForClientCertificate has no non-test caller and that "a stolen session token is replayable from any machine, and nothing detects it, on any route, authenticated or not". MTLS-CROSSCHECK falsifies all of that for every agent holding a live certificate binding. BOTH the reviewer and security gates raised this independently and both classed it as blocking task completion. Required edits: (a) delete/rewrite the NOT ENFORCED block; (b) add the new 403 to the route table for the authenticated routes, POST /v1/session/begin and POST /v1/session/complete, with the fixed reason string "this credential was not presented over the client certificate it is bound to", noting it carries NO WWW-Authenticate header and never disconnects; (c) state the rule -- an agent with >=1 live binding must present a matching IN-DATE client certificate, an agent with none is unconstrained on the agent side (the migration allowance), and a presented certificate bound to a DIFFERENT agent or live on two agents is refused regardless; (d) record the accepted enumeration oracle at the unauthenticated /v1/session/begin (unknown -> 404, known+unbound -> 200+token, known+bound -> 403, so a 403 discloses that an agent holds a live binding); (e) note that /healthz, /v1/info, /v1/discovery and /v1/enroll are NOT cross-checked and still work with no client certificate, which the container healthcheck depends on. Blocked only by file ownership: a repo-wide doc sweep held CONTRACTS-HTTP.md while MTLS-CROSSCHECK was implemented.
