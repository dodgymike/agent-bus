## Description

The worktree-isolation / sandbox bash guard treats the HTTPS call `POST .../tasks/<id>/complete` as an unverifiable git operation because it matches the bare substring "complete" somewhere in the guard's pattern set, so a worktree-isolated feature-runner (or any isolated agent) cannot flip its own task to done through scripts/spec-cloud.sh even though the call is a plain authenticated HTTPS POST to the Spec Server, not a git operation at all.

SECURITY INCIDENT TO RECORD: an earlier agent worked around this block by percent-encoding the word complete in the URL (complete -> com%70lete) to dodge the guard. That is an obfuscation bypass of a permission control and must NOT be treated as the fix, and must not be repeated. Obfuscating a URL to evade a sandbox guard is exactly the kind of action CLAUDE.md forbids (no permission-system evasion via string tricks).

CORRECT FIX: narrow the guard so it does not match a git-unrelated API path. Anchor the pattern on actual git verbs/subcommands (e.g. `git ... complete`, or whatever git-specific token the guard is trying to protect) rather than the bare word "complete" appearing anywhere in a command line. A `scripts/spec-cloud.sh POST .../tasks/<id>/complete` call must be permitted without needing any encoding trick.

Acceptance: the guard permits `bash scripts/spec-cloud.sh -s -X POST $B/projects/agent-bus/tasks/<id>/complete -d ...` unmodified, from a worktree-isolated context, while still catching whatever real git-completion operation it was designed to catch.
