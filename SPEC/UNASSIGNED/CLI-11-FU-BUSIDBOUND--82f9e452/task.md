## Description

Follow-up to CLI-11 (bf966c07-5f99-4fe6-bb23-52868ed04c33), security gate P2-3. PRE-EXISTING, not introduced by CLI-11.

readBusIDFile in internal/ids/busid.go reads the bus-id file with a bare os.ReadFile and validates the contents only afterwards, so the whole file is allocated before anything decides it is implausible. internal/buscert caps every file it reads at 64 KiB (maxKeyFileSize) for exactly this reason; bus-id has no such cap.

The path is shared by server startup, `agent-bus invite mint`, `agent-bus peer add` and now `agent-bus key export-public`, so an oversized bus-id file in a data directory is a startup-time allocation in every one of them. Reaching it needs write access to the 0700 data directory, which is why this is P2 rather than higher.

PROPOSED: read through an io.LimitReader with the same 64 KiB cap internal/buscert uses, and refuse anything longer rather than truncating -- a truncated bus id would be a DIFFERENT, plausible-looking bus id, which is worse than an error (invariant 2).

OUT OF SCOPE for CLI-11: internal/ids was outside its file boundary.
