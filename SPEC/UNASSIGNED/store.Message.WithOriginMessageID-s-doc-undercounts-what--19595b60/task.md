## Description

Found 2026-08-16 by the REVIEWER gate on RELAY-24-FU-STOREMSGLOOKUP-SIGCOPY, reported as out of that task's boundary and explicitly asked to be filed separately rather than folded in.

== THE DEFECT ==

internal/store/message.go, in WithOriginMessageID's doc comment:

    // The returned copy SHARES Body, Recipients and BusPath with the receiver, and
    // that is safe rather than an oversight: a Message is immutable after
    // construction -- NewMessageWithBusPath copies every slice on the way in, Append
    // stores that copy, and copyMessage copies again on the way out -- so no holder
    // of either value mutates the shared arrays.

The implementation is `out := m; out.OriginMessageID = originMessageID; return out`, which shares ALL FOUR slice fields. Signature is missing from the list.

== WHY IT IS WORTH A TASK RATHER THAN A DRIVE-BY ==

This is EXACTLY THE SAME CLASS OF ERROR as the defect that produced RELAY-24-FU-STOREMSGLOOKUP-SIGCOPY: copyMessage's doc said 'the two slices' while the function handled three, and the field the prose forgot -- Signature -- was the field the CODE forgot too. An undercount in prose is how the next maintainer learns the wrong ownership rule. Same field, same omission, adjacent function.

Pre-existing at HEAD 9938eb2 and NOT introduced by the SIGCOPY change. The behaviour is CORRECT as written -- the sharing genuinely is safe, and the safety argument is now STRONGER than when it was written, because copyMessage clones Signature too as of SIGCOPY. Only the enumeration is wrong.
