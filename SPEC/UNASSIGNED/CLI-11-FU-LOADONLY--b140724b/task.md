## Description

Follow-up to CLI-11 (bf966c07-5f99-4fe6-bb23-52868ed04c33), raised by its reviewer and security gates.

THE GAP. internal/buscert has no load-only entry point: LoadOrCreate GENERATES a certificate and two private keys when a data directory holds none of the three. internal/ids.LoadOrCreateBusID likewise CREATES a bus id when the file is absent, and unlike buscert it has no Generated() flag a caller can check afterwards. Every read-only consumer therefore has to defend itself with a stat-before-load dance: `agent-bus key export-public` (cmd/agent-bus/key.go) checks all four identity files before the lock AND again after it, then checks material.Generated() as a backstop, and `agent-bus invite mint` does the same for two of them.

TWO CONSEQUENCES, both P2 and both evidenced.

(1) SECURITY GATE P2-1: the ids half is not fully closed. If bus-id is removed in the window between key export-publics post-lock stat and its LoadOrCreateBusID call, a fresh bus id is minted and durably persisted, renaming the bus away from its own certificate. The export is still refused -- the CommonName cross-check catches it and no key is reported -- but a command documented as read-only has written. Verified live by the gate: exit 4 with "the certificate names bus X but this data directorys bus id is Y". It needs write access to a 0700 data dir, so no privilege boundary is crossed.

(2) REVIEWER P2: buscert.LoadOrCreate validates the certificates DATE WINDOW on the way to loading the signing key (ErrExpired, internal/buscert/buscert.go). So an EXPIRED TLS CERTIFICATE makes `agent-bus key export-public` exit 1, even though the Ed25519 signing key it would print is entirely independent of the certificate. An operator whose cert has expired cannot export the key a peer needs to keep verifying messages that originated on that bus -- exactly when they most need it. Documented as a known wart in CONTRACTS-CLI.md.

PROPOSED: add buscert.Load (load-only, never generates, and ideally able to return the signing material without asserting the certificates validity window) and ids.LoadBusID (load-only). Then delete the defensive stat dances from key export-public and invite mint and call the load-only forms. Do NOT weaken the never-mint property while doing it: the presence checks may only be removed once the load-only accessors make the mint branch structurally unreachable, and the tests that assert a refused command leaves the data directory EMPTY must stay green (TestKeyExportRefusesADirectoryWithNoKeyMaterial, TestInviteMintSubcommand/a_refusal_on_a_virgin_data_directory_leaves_it_COMPLETELY_untouched).

OUT OF SCOPE for CLI-11 because internal/buscert and internal/ids were outside its file boundary.
