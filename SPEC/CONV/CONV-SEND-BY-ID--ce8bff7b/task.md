## Description

The point of the whole epic, in the operator's words: clients "send using the uuid to send messages
rather than track the other participants in the conversation."

Sending to a conversation id resolves to the CURRENT membership AT SEND TIME, server-side. The
client does not enumerate participants and must not need to.

DELIBERATE CONTRAST WITH BROADCAST, and it matters: `store.Message.Broadcast` is stored as a FLAG
rather than an expanded recipient list precisely because expanding it "would freeze the roster as it
stood at send time into the durable record, which is both larger and wrong"
(internal/store/message.go:200-208). **A conversation is the OPPOSITE case** -- its audience is
EXPLICIT and bounded, and the signing layer already covers a sorted, deduplicated recipient list
(internal/signing/canonical.go:236-292). Decide and DOCUMENT whether the durable record stores the
expanded recipient list (signature-covered, auditable, freezes the roster at send time -- which for
a conversation is CORRECT, since membership at send time is exactly what authorised delivery) or a
conversation-id reference. Both are defensible; the reasoning must be written down, and it must
engage with the broadcast comment above rather than ignoring it.

INVARIANT 6: the audit record carries `recipients` PLURAL already
(internal/store/message.go:245-255), and it carries METADATA AND ROUTING ONLY -- never bodies.

BOUND: `store.MaxRecipients = 64` is the OPERATIVE durable bound (internal/store/message.go:72), NOT
`signing.MaxRecipients = 4096` (internal/signing/canonical.go:65). `internal/relay/signed_test.go:667`
asserts store <= signing. A conversation cannot exceed 64 participants without changing the durable
bound, and changing it needs its own justification. State the limit in the CLI help and
AGENT_PROTOCOL.md -- an agent must not discover it by being refused.

INVARIANT 7 (same task, non-negotiable): ship the `cmd/agent-busctl` subcommand AND the
AGENT_PROTOCOL.md entry IN THIS TASK. `--json` everywhere, stable documented exit codes, no
interactive prompt. `scripts/bus-*.sh` wrappers are RETIRED; adding one is FORBIDDEN. The client
package cannot live under `internal/`. Verify through the COMPILED CLI against a running server --
never hand-written curl.

Definition of done:
  1. Send-to-conversation-id route resolving membership server-side.

  3. The expanded-list-vs-reference decision written down with reasoning.
