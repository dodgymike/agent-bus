## Description

Durability/recovery evidence for the conversation record and the membership-change record.
**"The code looks right" is NOT evidence for a durability claim** -- CLAUDE.md requires a test that
writes, kills at a chosen point in the write path, and asserts what recovery yields.

INVARIANTS 4 AND 5 IN FULL BEFORE STARTING. Also invariant 6: a damaged conversation record is
DISCARDED and the bus still starts -- but **every discard must be logged loudly and specifically;
silent discard is the defect.** Invariant 1: when recovery discards a record the sequence ADVANCES
PAST THE HOLE, it never rewinds, and a conversation id is never reissued.

Cases the suite must cover, each a kill at a chosen point:
  1. Kill between PREPARE and COMMIT of a conversation-create. Recovery must NOT present a
     half-created conversation, and the id must not be reissued.
  2. Kill after COMMIT but before the acknowledgement reaches the client. The conversation MUST
     exist on recovery -- this is invariant 4's whole point -- and the client's retry under the same
     idempotency key must return the ORIGINAL conversation (see CONV-IDEM).
  3. Kill between the membership change and the change-event fan-out. Assert the JOIN POINT and the
     membership agree after recovery -- CONV-JOINPOINT's atomicity claim is proved HERE, not by
     reading the code.
  4. A torn/damaged conversation record in the tail: discarded, LOGGED SPECIFICALLY, bus starts.

Definition of done: the four cases above as tests, each asserting recovery output rather than
asserting the code path taken. Follow the existing crash-injection suite's shape (see the DUR epic's
work on the write path) rather than inventing a second harness.

Parallel-safety: touches internal/wal and internal/hub -- heavily contended by DUR and RELAY.
Coordinate before starting.
