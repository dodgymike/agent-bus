## Description

INVARIANT 10, READ IN FULL BEFORE STARTING. Three cases that must NOT be collapsed, plus one that
is specific to this epic.

  1. **Same key + SAME payload** on conversation create is a LEGITIMATE RETRY: return the ORIGINAL
     conversation, do NOT create a second, do NOT re-apply, **do NOT disconnect**.
  2. **Same key + DIFFERENT payload** (e.g. the same key with a different recipient list, or a
     different name) is a PROTOCOL VIOLATION: reject and LOG it, **do NOT disconnect**.
  3. **The RECIPIENT-CHANGE EVENT must not be delivered twice on a retry, and a duplicate change
     event must NOT be treated as a SECOND change.** These are two distinct failures: the first
     duplicates a delivery, the second corrupts membership state by applying a change twice. A
     remove-then-remove that lands twice must be idempotent in EFFECT, not merely in delivery.

  Only replay of an already-accepted SIGNED message disconnects, and only when the sender claim
  inside the signed bytes is a well-formed fully-qualified id. **BEFORE PROPOSING ANY DISCONNECT
  HERE, ANSWER INVARIANT 10'S TWO QUESTIONS: can a merely BUGGY client reach this line, and does
  this connection carry only ONE principal's traffic?** For a relayed conversation event the second
  answer is NO -- a peer connection carries many principals -- so a disconnect there punishes
  bystanders.

Idempotency must be DURABLE ACROSS RESTART (invariant 10). Reuse the existing applied-key store
(`internal/idem`) rather than inventing a second mechanism; note the existing tension recorded in
IDEM-FU-RESULTBYTES-VS-MAXRECIPIENTS (`idem.MaxResultBytes` vs `store.MaxRecipients`) -- a
conversation result carrying a 64-entry recipient list may hit exactly that bound. Check it and say
so.

Definition of done: the three cases above as tests, each asserting the DISTINCT outcome, plus a
restart test proving durability of the key. No disconnect added without the two questions answered
in the task notes.

Parallel-safety: touches internal/idem and internal/hub -- contended.
