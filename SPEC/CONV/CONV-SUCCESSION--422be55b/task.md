## Description

DECISION TASK, raised by the CONSEQUENCE of the operator's answer rather than by the answer
itself. The operator said "only the channel creator may change the receipient list, or an admin".
That is clean; its implication is not.

**THE PROBLEM:** if only the creator may change membership, what happens when the creator's agent id
disappears? Two concrete ways that happens in THIS system, neither hypothetical:
  - an agent that never re-enrols;
  - a name whose SUFFIX ADVANCED, so `<bus>.planner-3` is gone and `<bus>.planner-4` is a
    DIFFERENT principal (invariant 2: ids are fully qualified; invariant 1: never reused). The new
    agent is NOT the old creator and must not inherit its rights by name.

The conversation then becomes **PERMANENTLY FROZEN**: nobody may add or remove anyone, ever. It is
also unbounded retained state, which feeds straight into CONV-LIFECYCLE.

CANDIDATE RULINGS (pick one, with reasoning):
  - `ADMIN_ESCAPE_HATCH` -- the admin arm is the intended remedy. **If this is the ruling, the admin
    principal becomes LOAD-BEARING rather than optional**, which materially sharpens the INVMINT-2
    dependency: CONV then cannot be considered complete on the creator arm alone, and INVMINT-2 (P3,
    itself blocked by INVMINT-1) is on CONV's critical path. Say so explicitly and tell the operator.
  - `SUCCESSION_TRANSFER` -- creator rights transfer by some rule. Specify it; note it is a NEW
    authorization concept the operator did not ask for.
  - `FROZEN_BY_DESIGN` -- acceptable, membership is immutable after the creator leaves. Then state
    what bounds the retained state.
  - `CONVERSATION_EXPIRES` -- the lifecycle rule collects it. Coordinate with CONV-LIFECYCLE.

Definition of done:
  1. docs/conv/SUCCESSION-DECISION.md with a `RULING:` line from the set above, the reasoning, and
     an explicit statement of whether INVMINT-2 is thereby on CONV's critical path.
  2. Explicit treatment of the suffix-advance case -- a re-enrolled agent with a NEW suffix must NOT
     inherit creator rights.
  3. Reported to the operator; a DECISIONS.md entry.
