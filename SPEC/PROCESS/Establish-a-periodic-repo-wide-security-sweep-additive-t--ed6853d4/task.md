## Description

Add a security pass that is not attached to any task. Per-task review structurally cannot see cross-task interactions, accumulated attack surface, or invariant drift -- every pass is scoped to one change by construction. This is additive; it does not replace the per-task gate.

Definition of done: a documented cadence and scope, a defined artefact (where findings land -- filed tasks, not a report nobody reads), and one sweep actually run with its findings filed. The first sweep's value is partly in establishing a baseline, so its output being large is expected rather than alarming.

Seed it with something already known: this session found four separate tasks (c20c15c8, c66dd902, 1691873b, a4d80a44) all describing the same TestCLIEnrolEndToEnd harness race. Backlog duplication of that kind is exactly what a sweep should surface and consolidate.

AMENDED 2026-08-22 (tiered chain): this becomes MORE necessary, not less. Under tiering, T0/T1/T2 changes receive reduced or no per-task security scrutiny by design, so the sweep is the only pass that ever sees them. The sweep's scope must explicitly include everything that measured T0/T1/T2 since the previous sweep -- that set is enumerable from the kind=tier notes, so the sweep has a defined, mechanical input rather than 'the whole repo'.
