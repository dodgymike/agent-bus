## Description

SYMPTOM: bash scripts/gen-spec-mirror.sh --no-relations currently refuses to run, so SPEC.md and SPEC/ cannot be regenerated by the only supported path. Exact refusal output (verified live, 2026-08-21, exit code 1):

gen-spec-mirror: REFUSING TO WRITE -- the markdown export is not the shape this script expects.
  unexpected non-blank column-0 lines: 15

  markdown heading or fence and the exporter stopped indenting descriptions.

THE GUARD IS CORRECT and its second hypothesis is the right one -- do NOT soften this refusal into a warning that writes anyway. A silently-wrong mirror is worse than no mirror; the whole point of the guard is that it refuses rather than emit a mirror that lies.

ROOT CAUSE: the Spec Server's markdown exporter renders a task's proof_cmd as a trailing italic-wrapped blob (a "Proof: <cmd>" span). When that proof_cmd is a MULTI-LINE shell script, only the FIRST line is indented by the exporter -- every continuation line is emitted at column 0, which trips gen-spec-mirror.sh's shape guard (it expects every non-blank line of a task record to be indented under that task's heading).

Fifteen such column-0 lines currently come from one task's proof_cmd: the reservation-counter-drift investigation task (public_id dd2cdc20-8920-4e5b-bf0a-668f439cc3a6, title "Reservation counters silently drift stale and hand out COLLIDING task keys (RELAY, DOCS, ACK, AUTH)", component=process, status=todo). Its proof_cmd is a multi-line bash script starting with a variable assignment using mktemp and a trap for cleanup, running through a final exit statement. In the broken export, the closing exit line is rendered fused to the italic span's closing marker (an underscore glued onto the end), which is itself evidence the exporter is wrapping the ENTIRE multi-line value in one inline-italic markdown span rather than a block construct -- inline spans do not carry per-line indentation, so every line after the first lands at column 0.

Note: this defect is a property of the EXPORTER/GENERATOR pairing in general, not specific to that one task's proof_cmd. If that task's proof_cmd is later shortened or rewritten, THIS symptom may stop reproducing via that particular task, but the underlying defect remains latent and will resurface on the next multi-line proof_cmd anyone writes. This task is about the exporter/generator shape, not about editing that task's proof_cmd.

TWO CANDIDATE FIXES (pick one; scope/decide which is right, do not just implement blind):
1. Fix the exporter (upstream, Spec Server side) so it indents every continuation line of a multi-line proof_cmd under the task heading, the same way it already indents description continuation lines -- OR renders a multi-line proof_cmd as a fenced block instead of an inline-italic span, since inline spans cannot carry per-line indentation at all.
2. Fix gen-spec-mirror.sh (repo side) so its shape guard tolerates a proof block whose first line is indented and whose continuation lines are not, when it can positively identify that the whole block belongs to one task's proof_cmd rather than being genuinely truncated output or a stray heading/fence inside a description. This must not weaken the guard's ability to catch actual truncation or a genuine column-0 heading/fence leaking out of a description -- those are the failure modes the guard exists to catch, and it must keep catching them.

CONSEQUENCE, stated so nobody commits blind: 178 SPEC.md/SPEC/ entries are currently dirty in the working tree from an earlier successful regeneration run that pre-dates this proof_cmd landing, and they CANNOT be re-verified by regeneration until this is fixed, because every gen-spec-mirror.sh invocation since has refused outright. Do not commit those 178 dirty entries on the strength of a run that never completed. CLAUDE.md's rule that gen-spec-mirror.sh is the ONLY supported way to write SPEC.md or SPEC/ still holds -- do NOT work around this by running the raw export command directly into SPEC.md; that is the specific failure mode CLAUDE.md warns against (it silently overwrites the index with an error page on a failed fetch, and it puts the old single-file mirror shape back over the index either way).
