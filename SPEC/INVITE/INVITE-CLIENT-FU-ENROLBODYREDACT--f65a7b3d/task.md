## Description

DISCOVERED BY: reviewer/security gate during INVITE-CLIENT (4123e25d-4644-48e0-9ee1-e0a9a273fd8c)

`internal/httpapi.EnrolRequestBody` holds `InviteSecret`, a bearer credential, and is the ONLY secret-bearing struct in the repo without a redacting `String()`/`GoString()`. Its doc comment asserts the secret is "NEVER LOGGED, NEVER ECHOED AND NEVER APPEARS IN AN ERROR", but nothing STRUCTURALLY enforces that: any `%v` of the struct prints it. The client side already does this correctly (`client.Invite` has both, on value receivers). Add the same on the server side so the guarantee is structural rather than by discipline.
