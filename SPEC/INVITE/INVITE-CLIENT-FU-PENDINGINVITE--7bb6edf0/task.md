## Description

DISCOVERED BY: reviewer/security gate during INVITE-CLIENT (4123e25d-4644-48e0-9ee1-e0a9a273fd8c)

`client/store.go`'s `pendingEnrolment` does not record the invite id, so resuming an interrupted enrolment with `--idempotency-key` and a DIFFERENT invite file is caught by the BUS (409, since the server's idempotency fingerprint covers `invite_id`) rather than locally. The same mistake with a different NAME is refused locally without a round trip. Recording the invite id beside the key material would close it. The ID only -- never the secret, which must never be persisted. Documented as a KNOWN GAP in a comment in `client/enrol.go`.
