## Description

client/enrol.go:790-791 annotateInviteRefusal returns early on inv==nil, so a no-invite 403 (now live thanks to INVITE-GATE-ENFORCE, 8297d7e2) surfaces with statusError generic KindAuth remedy: "the session may have expired or the bus may have restarted; retry, and if it persists re-enrol" -- wrong on every clause (no session exists; retrying can never succeed against an invite-only bus) and it frames the refusal as "rejected this credential" when no credential was presented at all. Fix: add a sibling annotator that fires on 403 + inv==nil (i.e. no invite was ever supplied) and sets Remedy to something that WORKS, e.g. "this bus is invite-only; obtain an invite from the operator and pass --invite-file <path>". This is invariant 7 territory: an error surfaced by the compiled CLI must name a remedy that actually works, not one that sends an agent into an infinite retry loop against an unauthenticated route (which also feeds the log-amplification surface AUTH-1-FU-RATELIMIT is meant to bound). Also fix client/enrol.go:63-66 -- EnrolOptions.Invite doc currently says nil "is still accepted, because the bus still accepts an un-invited enrolment"; this is false now and client/ is the published non-internal package (invariant 7) so its doc comments are load-bearing. client/ is clean in git -- verify before editing.

Proof: a new/updated client test asserts that a 403 with no invite presented yields a Remedy string that does NOT contain "retry" and DOES mention --invite-file, confirmed RED before the fix (current annotateInviteRefusal leaves the generic KindAuth remedy in place) and GREEN after.
