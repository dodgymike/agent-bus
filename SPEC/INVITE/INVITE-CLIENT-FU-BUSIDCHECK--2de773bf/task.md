## Description

DISCOVERED BY: reviewer/security gate during INVITE-CLIENT (4123e25d-4644-48e0-9ee1-e0a9a273fd8c)

`client.Invite.BusID` is carried but never checked: `Validate` does not constrain it and `Enrol` does not compare it with the `bus_id` the SERVER returns. The server is authoritative on ids (invariant 1), so the field is a claim by whoever wrote the blob. Cross-checking it would catch a substituted-blob case earlier and with a clearer message than a certificate mismatch does. INVITE-CLIENT corrected the misleading doc comment rather than adding the check. Note the field is unvalidated, so it must stay `safeText`-bounded wherever it is rendered.
