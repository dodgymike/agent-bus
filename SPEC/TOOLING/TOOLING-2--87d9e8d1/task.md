DEPLOY-6 verified docs/THREE-BUS-DOCKER.md by EXTRACTING every ```bash block from Sections 3.1-3.9 out of the markdown and running them verbatim -- which is what caught a broken `ctl()` helper (the -v flag placed after the image name instead of before it) that both the reviewer and security gate also flagged independently. Wanted: make that extraction a repeatable script/check (e.g. scripts/verify-three-bus-runbook.sh or similar) that pulls every ```bash fenced block out of docs/THREE-BUS-DOCKER.md in document order, runs them against a real docker daemon standing up the three-bus A<->B<->C setup, and fails loudly (non-zero exit, no silent pass) if any command in the sequence fails -- so the runbook cannot silently drift from a working three-bus setup as the CLI surface changes. Must not require host tooling beyond docker (per DEPLOY-6's environment notes: image-only verification, no host Go toolchain) and must not invent a new bus-*.sh wrapper (invariant 7 -- retired, only bus-serve.sh survives).
