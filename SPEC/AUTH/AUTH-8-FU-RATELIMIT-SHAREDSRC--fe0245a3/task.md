## Description

From AUTH-8 deep dive (gap G8). internal/httpapi/ratelimit.go keys the per-source token bucket on remoteHost(r) (TCP peer, port stripped, proxy headers ignored; ratelimit.go:193-201). Behind the Docker bridge EVERY container appears as 172.17.0.1; behind NAT/reverse-proxy/SSH tunnel many agents collapse to ONE bucket and throttle each other. The shipped runtime is a container on the Docker bridge, so this is the COMMON case. At the default 5/s + burst 60 a synchronised reconnect storm (bus restart, orchestrator boot, batch agent start) -- all on the three UNauthenticated credential routes -- exhausts one shared bucket and honest co-located agents get 429s. Self-heals (Retry-After) but the abuse control's blast radius includes legitimate neighbours. Evaluate: (a) confirm only the three unauthenticated routes are billed to the IP bucket and document that a reconnect storm is entirely on those routes so an authenticated fast-path does not help; (b) raise/tune the default burst for expected co-located fan-out with operator guidance; (c) per-(source, PROVEN-agent-id) sub-bucketing on /v1/session/complete ONLY -- NOT /v1/session/begin, where the id is attacker-supplied and any per-id bucket is a lockout primitive (invariant 3; session.go:229-240). Unauthenticated hot path + abuse surface: full chain incl. security gate mandatory. proof_cmd sketch asserts co-located distinct principals are not starved by one source's burst.
