## Description

Filed 2026-08-14 per coordinator decision, low priority, sits below the critical path.

Motivating incidents from a single session: RELAY-44/RELAY-45 (two agents independently filed the same inbound-peer-certificate-binding gap 39 seconds apart) and the RELAY-43/RELAY-46 near-miss (a reserved-but-uncreated task-key number that could have collided the same way). Both were caught only by manual reconciliation after the fact -- one agent noticing two similarly-titled tasks in the same epic.

SCOPE: a cheap, non-blocking similarity check (substring/trigram/fuzzy title match against OPEN tasks in the same epic_key, run at task creation and/or surfaced on claim-next) that WARNS rather than rejects -- two agents legitimately filing adjacent-but-distinct work in the same area is normal and must not be blocked. This detects the SYMPTOM.

NOTE THE BETTER FIX, RECORDED HERE SO IT ISN'T LOST: the actual cause is that follow-ups get filed by whichever agent notices the gap, rather than by the task whose review/security/implementation pass discovered it. A convention where discovered follow-ups are filed ONLY by the owning task (or its explicitly assigned agent) removes the race entirely, rather than detecting it after the fact. This detector is a cheap mitigation, not a substitute for that convention -- if the convention is adopted project-wide, this task's value drops to a backstop for the cases where it wasn't followed.

Out of scope: blocking/rejecting a create on similarity match (too many legitimate false positives -- e.g. this project's own MTLS-* and RELAY-* families share vocabulary constantly), and any change to claim-next's atomicity guarantee.
